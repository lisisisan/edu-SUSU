### **1. Для какого класса архитектур предназначена гибридная (MPI + OpenMP) технология программирования?**

Гибридная технология **MPI + OpenMP** предназначена для **многоуровневых (кластерных) вычислительных систем**, в которых:

* узлы связаны между собой сетью (распределённая память → MPI),
* внутри каждого узла — несколько ядер или потоков (общая память → OpenMP).

То есть — **архитектура с распределённой и общей памятью одновременно (кластер многопроцессорных узлов)**.

---

### **2. Какими объектами ОС она оперирует?**

* **MPI** оперирует **процессами** — независимыми экземплярами программы, у каждого своя память.
* **OpenMP** оперирует **нитями (threads)** внутри одного процесса, которые используют общую память.

Гибридная модель работает сразу с **процессами и потоками**.

---

### **3. Не противоречит ли ответу на предыдущий вопрос запуск данной программы на Вашем ноутбуке? Какую архитектуру он имеет?**

Нет, не противоречит.
Мой ноутбук — **многоядерная система с общей памятью (SMP)**.
Хотя он не кластер, **MPI просто создаёт несколько процессов на одном устройстве**, а OpenMP — несколько потоков внутри каждого процесса.
То есть программа **эмулирует** работу кластера на локальной машине.

### **4. Можно ли в коде поменять порядок вложения MPI и OpenMP (вызвать MPI_Init / MPI_Finalize внутри параллельного региона OpenMP)? Почему?**

Нет, **нельзя**.
`MPI_Init` и `MPI_Finalize` должны вызываться **вне параллельных регионов OpenMP**, потому что:

* эти функции инициализируют / завершают коммуникацию между процессами (глобально),
* MPI не потокобезопасен по умолчанию,
* внутри `#pragma omp parallel` может быть несколько потоков — инициализация MPI каждым потоком приведёт к ошибкам.

Правильный порядок:

```cpp
MPI_Init();
#pragma omp parallel { ... }
MPI_Finalize();
```

### **5. Прокомментируйте порядок вывода номеров процессов и нитей.**

Вывод **неупорядочен**, потому что:

* процессы MPI выполняются **параллельно и независимо**,
* потоки OpenMP внутри каждого процесса тоже выполняются **параллельно**.

Поэтому строки могут печататься вперемешку: порядок вывода не гарантируется.
Чтобы избежать «каши», можно использовать `#pragma omp critical` или `printf` с `fflush(stdout)`.

### **6. Исходя из каких соображений в Задании № 32 выбран способ распределения итераций по процессам?**

Выбор сделан для **равномерной загрузки всех процессов**:
каждый процесс берёт итерации с шагом `size`, то есть:

```cpp
for (i = rank; i < N; i += size)
```

Таким образом:

* все процессы выполняют примерно одинаковое количество шагов,
* не нужно пересылать большие блоки данных,
* нагрузка сбалансирована, и коммуникации минимальны.

---

### **7. Исходя из каких соображений в Задании № 32 выбран способ распределения итераций по нитям (статический/динамический, размер чанка)?**

В OpenMP используется **статическое распределение** (`#pragma omp for` без schedule).
Это сделано потому что:

* вычислительная нагрузка на каждой итерации одинакова,
* динамическое распределение дало бы лишние накладные расходы (overhead),
* статическое распределение быстрее при равномерных задачах (как интеграл для π).
