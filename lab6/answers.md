**1. В чем отличие широковещательной коммуникации от коммуникации "точка-точка"?**

* **Точка-точка (point-to-point)** — обмен данными осуществляется между конкретными парой процессов: один отправитель, один получатель. Для передачи сообщения нужно явно указать отправителя и получателя, а каждый процесс сам инициирует операции `MPI_Send` и `MPI_Recv`.
* **Широковещательная (broadcast)** — один процесс (root) рассылает одно и то же сообщение всем процессам коммуникатора одновременно. Остальные процессы автоматически получают сообщение без явного вызова отправки. Таким образом, уменьшается код и повышается эффективность при массовой рассылке.

---

**2. Назначение и параметры функции `MPI_Bcast`.**
`MPI_Bcast` используется для широковещательной рассылки данных от одного процесса (root) всем остальным процессам в коммуникаторе.

Синтаксис:

```c
int MPI_Bcast(void* buffer, int count, MPI_Datatype datatype, int root, MPI_Comm comm);
```

* `buffer` — указатель на данные, которые нужно передать (для root — данные для отправки, для остальных — место для приёма).
* `count` — количество элементов для передачи.
* `datatype` — тип данных элементов (`MPI_INT`, `MPI_CHAR`, `MPI_DOUBLE` и т.д.).
* `root` — номер процесса, который рассылает данные.
* `comm` — коммуникатор, в котором происходит рассылка (обычно `MPI_COMM_WORLD`).

Особенность: все процессы вызывают `MPI_Bcast`, иначе может возникнуть зависание.

**3. Назначение и параметры функции `MPI_Reduce`.**
`MPI_Reduce` выполняет редукцию (агрегирование) данных с нескольких процессов в один результат на корневом процессе.

Синтаксис:

```c
int MPI_Reduce(void* sendbuf, void* recvbuf, int count, MPI_Datatype datatype, MPI_Op op, int root, MPI_Comm comm);
```

* `sendbuf` — указатель на данные для отправки каждым процессом.
* `recvbuf` — указатель на буфер для получения результата на корневом процессе (остальные процессы игнорируют этот буфер).
* `count` — количество элементов для редукции.
* `datatype` — тип элементов.
* `op` — операция редукции: `MPI_SUM`, `MPI_MAX`, `MPI_MIN`, `MPI_PROD` и т.д.
* `root` — номер процесса, на котором будет результат.
* `comm` — коммуникатор.

Особенности:

* На **root-процессе** результат сохраняется в `recvbuf`.
* На **остальных процессах** `recvbuf` игнорируется, они только участвуют в вычислениях.

**4. Назначение и параметры функций `MPI_Scatter` и `MPI_Gather`.**

* `MPI_Scatter` — распределяет блоки данных от одного процесса (root) всем процессам.

  ```c
  int MPI_Scatter(void *sendbuf, int sendcount, MPI_Datatype sendtype,
                  void *recvbuf, int recvcount, MPI_Datatype recvtype,
                  int root, MPI_Comm comm);
  ```

  * `sendbuf` — буфер с данными на root-процессе.
  * `sendcount` — количество элементов, посылаемых каждому процессу.
  * `recvbuf` — буфер для приёма на каждом процессе.
  * `recvcount` — количество элементов, которое каждый процесс получает.
  * Остальные параметры: `datatype`, `root`, `comm`.

* `MPI_Gather` — собирает блоки данных от всех процессов в один буфер на root-процессе.

  ```c
  int MPI_Gather(void* sendbuf, int sendcount, MPI_Datatype sendtype,
                 void* recvbuf, int recvcount, MPI_Datatype recvtype,
                 int root, MPI_Comm comm);
  ```

  * `sendbuf` — данные, отправляемые каждым процессом.
  * `recvbuf` — буфер на root-процессе для сборки результатов.
  * Остальные параметры аналогичны `MPI_Scatter`.

**5. Можно ли с помощью этих функций рассылать/собирать динамически выделенные двумерные массивы (матрицы)? Можно ли использовать их, если количество данных не кратно количеству процессов?**

* **Динамические двумерные массивы**: да, можно, но важно передавать их как **линейный массив (1D)**, т.е. строки подряд. MPI работает с непрерывной памятью, поэтому двумерные массивы нужно упаковать или выделять как один блок.
* **Если количество данных не кратно числу процессов**:

  * Для `MPI_Scatter`/`MPI_Gather` стандартная версия требует одинаковое количество элементов для всех процессов, поэтому используют расширенную версию `MPI_Scatterv` и `MPI_Gatherv`, где можно задавать разное количество элементов и смещения для каждого процесса.
