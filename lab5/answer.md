### **1. Общая схема межпроцессного обмена**

В MPI обмен сообщениями реализуется **точка-точка** или **коллективно**. Для схем типа «каждый каждому» / «кольцо» / «мастер-рабочие» общая схема:

**Участники:**

* **Отправитель (sender)** – процесс, который посылает данные.
* **Получатель (receiver)** – процесс, который принимает данные.
* **Коммуникатор** (`MPI_Comm`) – группа процессов, участвующих в обмене.

**Порядок действий при точка-точка:**

1. Процесс отправляет сообщение с помощью `MPI_Send` или `MPI_Isend`.
2. Процесс получатель вызывает `MPI_Recv` или `MPI_Irecv` для приема сообщения.
3. В блокирующем обмене отправитель ждёт завершения передачи (`MPI_Send`), в неблокирующем — используется `MPI_Wait`/`MPI_Waitall`.
4. При необходимости повторяется для всех участников обмена (например, в кольце или all-to-all).

### **2. Тип данных и общий формат функций**

**Данные, передаваемые в MPI:**

* MPI передает **гомогенные массивы** базовых типов: `MPI_INT`, `MPI_FLOAT`, `MPI_DOUBLE`, `MPI_CHAR` и др.
* Возможна передача **структур** через `MPI_Datatype` (напр., пользовательские типы).

**Общий формат функции передачи сообщений:**

```cpp
MPI_Send(void* buf, int count, MPI_Datatype datatype, int dest, int tag, MPI_Comm comm);
MPI_Recv(void* buf, int count, MPI_Datatype datatype, int source, int tag, MPI_Comm comm, MPI_Status* status);
```

**Параметры и их назначение:**

* `buf` — адрес буфера с данными.
* `count` — количество элементов.
* `datatype` — тип данных MPI.
* `dest` / `source` — идентификаторы процесса получателя или отправителя.
* `tag` — тег сообщения для различения сообщений.
* `comm` — коммуникатор (MPI\_COMM\_WORLD или другой).
* `status` — информация о принятом сообщении (от кого, размер и др.).

---

### **3. Классификации механизмов передачи сообщений в MPI**

**MPI делит обмен на:**

1. **По синхронизации:**

   * **Блокирующие**: `MPI_Send`, `MPI_Recv`
     — выполнение функции блокирует процесс до завершения отправки/приема.
   * **Неблокирующие**: `MPI_Isend`, `MPI_Irecv`
     — процесс инициирует передачу и может продолжать работу, контроль через `MPI_Wait`, `MPI_Test`.

2. **По направлению:**

   * **Точка-точка (point-to-point)**: один sender → один receiver.
   * **Коллективные (collective)**: `MPI_Bcast`, `MPI_Reduce`, `MPI_Alltoall` и др. — множество процессов участвует одновременно.

3. **По способу буферизации:**

   * **Стандартная**: MPI самостоятельно буферизует сообщение.
   * **Синхронная**: блокировка отправителя до начала приема.
   * **Буферизованная**: отправка в локальный буфер MPI.
   * **Режим ready**: предполагается, что приемник готов к приему.

### **4. Почему для каждой задачи использовался конкретный вид функций**

**Задание 11–12 (I am / FIRST-SECOND)**

* **Используемые функции:** `MPI_Init`, `MPI_Finalize`, `MPI_Comm_rank`, `MPI_Comm_size`
* **Причина выбора:** Простое получение номера процесса и общего количества процессов.
* **Эффективность:** Нет обмена между процессами, просто вывод информации.

**Задание 13 (эстафета)**

* **Используемые функции:** `MPI_Send`, `MPI_Recv` (блокирующие)
* **Причина выбора:** Последовательная передача «эстафетной палочки» — каждый процесс ждет предыдущий.
* **Эффективность:** Обеспечивает строгий порядок передачи, deadlock не возникает, прироста скорости нет, так как процессы выполняются последовательно.

**Задание 14 (master-slave)**

* **Используемые функции:** `MPI_Send`, `MPI_Recv` (блокирующие)
* **Причина выбора:** Master-процесс собирает данные от всех остальных процессов.
* **Эффективность:** Позволяет master-у дождаться всех сообщений от slave-процессов, упрощает контроль.

**Задание 15 (кольцо)**

* **Используемые функции:** `MPI_Isend`, `MPI_Irecv`, `MPI_Waitall` (неблокирующие)
* **Причина выбора:** Одновременный обмен сообщениями по кольцу, чтобы все процессы могли отправлять и принимать данные параллельно.
* **Эффективность:** Ускорение за счет параллельной отправки и приема, отсутствует блокировка на каждом шаге.

**Задание 16 (каждый каждому)**

* **Используемые функции:** `MPI_Isend`, `MPI_Irecv`, `MPI_Waitall` (неблокирующие)
* **Причина выбора:** Все процессы одновременно отправляют и принимают сообщения от всех остальных.
* **Эффективность:** Минимизация простоев, высокая производительность, определение отправителя через `source` в `MPI_Recv` или `MPI_Status`.

### **5. Как избежать синхронизации в порядке приема сообщений без смены функции**

* Используем **неблокирующие функции** `MPI_Irecv` + `MPI_Waitall`.
* **Каждый процесс инициирует все приема и отправки сразу**, затем ждет их завершения.
* **Определить отправителя** можно через `source` в `MPI_Recv` или `MPI_Status.MPI_SOURCE`:

```cpp
MPI_Status status;
MPI_Recv(&buf, 1, MPI_INT, MPI_ANY_SOURCE, 0, MPI_COMM_WORLD, &status);
int sender_rank = status.MPI_SOURCE;
```

* Так можно принимать сообщения в **любом порядке**, не блокируя процесс и без риска deadlock.
