### **1. Что такое MPI?**

* **MPI (Message Passing Interface)** — это стандарт (библиотека) для параллельного программирования, основанного на **обмене сообщениями** между процессами.
* Он реализует модель **распределённой памяти**: процессы обмениваются данными не напрямую через общую память, а отправкой/приёмом сообщений.
* MPI ориентирован на **кластерные архитектуры** (много узлов с собственной памятью, объединённых сетью), но может работать и на многопроцессорных машинах.
* В нашей системе (macOS + VS Code) он подключается установкой **OpenMPI** через `brew install open-mpi`, а в коде через:

  ```cpp
  #include <mpi.h>
  ```

### **2. Чем в MPI реализованы параллельно выполняемые подзадачи?**

* Подзадачи — это **процессы**. Каждый процесс — отдельный экземпляр программы.
* Запускаются они **одновременно** при старте программы через команду:

  ```bash
  mpirun -np <N> ./program
  ```

  где `-np <N>` указывает число процессов.
* Существуют процессы **с момента вызова `MPI_Init()`** и до **`MPI_Finalize()`**.
* Каждый процесс имеет свой **идентификатор (ранг, rank)** в коммуникаторе.

### **3. Что такое коммуникатор?**

* **Коммуникатор** — это объект, который определяет группу процессов, которые могут взаимодействовать между собой.
* Главный коммуникатор по умолчанию — **MPI\_COMM\_WORLD** (содержит все запущенные процессы).
* Внутри коммуникатора каждому процессу назначается **номер (rank)** от `0` до `N-1`.

### **4. Что делают функции `MPI_Init()` и `MPI_Finalize()`?**

* `MPI_Init(&argc, &argv)`
  → инициализирует среду MPI, распределяет процессы, подготавливает систему к обмену сообщениями.
* `MPI_Finalize()`
  → завершает работу MPI, освобождает ресурсы, синхронизирует процессы.
* Роль: они **обозначают границы MPI-программы**.
* Вызвать их можно только **по одному разу** в каждом процессе.

### **5. Для чего любой параллельной программе нужна информация о количестве процессов и ID текущего процесса?**

* Количество процессов (`MPI_Comm_size`) нужно, чтобы:

  * распределить задачи между процессами;
  * понимать общую «команду» процессов.
* Идентификатор процесса (`MPI_Comm_rank`) нужен, чтобы:

  * определить, **какой кусок работы** выполнять;
  * выбрать **ведущий процесс** (обычно `rank = 0`);
  * правильно организовать обмен сообщениями (кому отправить, у кого принять).

Без этих двух параметров невозможно разделить задачу и синхронизировать вычисления.
