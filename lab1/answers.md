### **1. Что такое OpenMP? Какие модели он реализует? Опишите модели и их связь.**

* **OpenMP** — это стандарт для параллельного программирования на многопроцессорных системах с общей памятью.
* Реализует две основные модели:

  * **Fork-Join** — при входе в параллельный регион создаётся команда потоков (fork), при выходе все потоки, кроме главного, завершают работу (join).
  * **SPMD (Single Program Multiple Data)** — все нити выполняют одну и ту же программу, но могут работать с разными данными.
* Связь: **Fork-Join** задаёт структуру параллельных регионов, а **SPMD** определяет способ выполнения кода в этих регионах.

### **2. В каких языках реализован этот стандарт? Из каких частей состоит реализация в Visual Studio?**

* OpenMP реализован в **C, C++ и Fortran**.
* В **Visual Studio** реализация OpenMP состоит из:

  * **директив препроцессора (pragma)** — описывают параллельные регионы и работу с циклами;
  * **библиотеки функций OpenMP** (`omp_get_thread_num`, `omp_set_num_threads` и др.);
  * **системы переменных окружения** (например, `OMP_NUM_THREADS`).

### **3. Какие существуют варианты задания количества нитей в параллельном регионе?**

1. Вызов функции **`omp_set_num_threads(n)`** в коде.
2. Переменная окружения **`OMP_NUM_THREADS`**.
3. Клаузула **`num_threads(n)`** внутри директивы `parallel`.

Если заданы **оба варианта с разными значениями**: приоритет имеет **клаузула `num_threads(n)` в коде**.

* **`omp_set_num_threads(n)`** — задаёт число нитей, которое будет использоваться в *следующих* параллельных регионах (если не переопределено локально).

### **4. Как идентифицируются нити в OpenMP? Для чего это нужно? Приведите содержательный пример. Совпадают ли эти идентификаторы с идентификаторами потоков в ОС?**

* Каждая нить имеет **свой номер (ID)** в пределах параллельного региона, который можно получить с помощью **`omp_get_thread_num()`**.
* Главная нить всегда имеет ID = 0.
* Нужно это для разделения работы между нитями, например:

  ```cpp
  #pragma omp parallel
  {
      int tid = omp_get_thread_num();
      cout << "Hello from thread " << tid << endl;
  }
  ```
* **Эти идентификаторы не совпадают** с системными идентификаторами потоков ОС — это логическая нумерация внутри OpenMP.


### **5. Каков порядок вывода сообщений нитями? Всегда ли он одинаков? Чем определяется этот порядок?**

* Порядок вывода **не фиксирован** — он зависит от того, какая нить первой получит доступ к стандартному выводу (stdout).
* Каждый запуск программы может давать **разный порядок** строк.
* Чтобы упорядочить вывод, можно использовать:

  * **критические секции** (`#pragma omp critical`),
  * или функции синхронизации (`#pragma omp barrier` + вывод по номерам нитей).
