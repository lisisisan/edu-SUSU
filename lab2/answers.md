**1. Для чего нужны частные переменные?**

* Частные переменные нужны для того, чтобы каждая нить имела собственную копию переменной и не мешала другим.
* Это **не противоречит модели общей памяти**, так как область памяти общая, но OpenMP создаёт локальные копии переменной в стеке каждой нити.
* **Пример**:

  ```cpp
  #pragma omp parallel private(x)
  {
      int x = omp_get_thread_num(); // у каждой нити своё значение
      printf("Thread %d has x=%d\n", omp_get_thread_num(), x);
  }
  ```

**2. Какие новые области видимости появляются в параллельной программе? Как задаются?**

* **private** – локальная копия у каждой нити, начальное значение не сохраняется.
* **firstprivate** – как `private`, но копия инициализируется значением из основной области.
* **lastprivate** – как `private`, но после завершения сохраняется значение из последней итерации.
* **shared** – общая переменная для всех нитей.
* **reduction** – каждая нить имеет свою копию, а после выполнения они объединяются по указанной операции.

**3. Конфликт обращений к переменной rank.**

* Конфликт возникает, если несколько нитей одновременно пишут в одну и ту же переменную:

  ```cpp
  int rank = 0;
  #pragma omp parallel
  {
      rank = omp_get_thread_num(); // конфликт записи
  }
  ```
* Возникает не всегда (зависит от планировщика и скорости выполнения), но может привести к некорректным данным.
* Предотвращение: использовать `private(rank)` или `omp_get_thread_num()` без общей переменной.

**4. Как оформляются входные данные, промежуточные переменные и результаты?**

* **Входные данные**: обычно `shared`, чтобы все нити могли читать.
* **Промежуточные переменные**: `private` или `firstprivate`, чтобы избежать конфликтов.
* **Результаты**: через `reduction`, `critical`, `atomic`, или в `lastprivate`.

**5. Что делает параметр reduction?**

* Создаёт локальные копии переменной для каждой нити.
* После завершения параллельного региона OpenMP объединяет все копии по указанной операции (`+`, `*`, `max`, `min` и др.).
* **Инициализация**:

  * сложение → `0`
  * умножение → `1`
  * `max` → минимальное значение типа
  * `min` → максимальное значение типа.
